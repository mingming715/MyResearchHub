  - title: "저비트에서 무너지는 PTQ 대신, 멀티모달부터 되살린다 — ProQuant의 2단계 QAT"
    type: "논문"
    summary: "엣지용 멀티모달 LLM(MLLM)을 저비트로 양자화하면 사후양자화(PTQ)는 중간 비트폭까지는 버티지만 W4A8 같은 저비트에서 정확도가 크게 무너진다. ProQuant는 이 문제를 양자화-인지 학습(QAT)으로 풀되, 순서를 뒤집은 것이 핵심이다 — 언어모델링 성능부터 복구하는 기존 방식과 달리, 먼저 '점진적 블록 활성화(PBA)'로 멀티모달 이해 능력을 되살린 뒤 언어 성능을 복구하고, 학습 데이터도 원본 라벨 대신 모델 자신이 재생성한 응답을 쓴다. Qwen3-VL-2B-Instruct를 W4A8로 양자화했을 때 평균 정확도가 6.6%p 개선되어 풀프리시전 모델과 격차가 약 1%로 좁혀졌다고 보고한다. NeurIPS 2026 포스터로 채택되어 동료 심사를 통과했지만, 공개된 GitHub 저장소는 아직 스타 1개로 이제 막 나온 결과라는 점은 감안해야 한다."
    source_url: "https://arxiv.org/abs/2611.08216"
  - title: "추측하고 다시 고친다 — LeanStream이 온디바이스 LLM 추론 메모리를 7배 줄이는 법"
    type: "논문"
    summary: "온디바이스 LLM 서빙은 메모리 용량이 가장 먼저 막히는 벽인데, 기존 추측 디코딩(speculative decoding)은 속도는 올리지만 초안 모델과 검증 모델을 동시에 메모리에 올려야 해서 엣지에서는 오히려 부담이 된다. LeanStream은 '추측하고 다시 정제한다(speculate-and-refine)' 방식의 스트리밍 프레임워크로, 토큰을 통째로 버리거나 전부 검증하는 대신 스트리밍 방식으로 생성과 보정을 겹쳐 처리해 메모리 상주량을 줄인다. 기존 최고 처리량 대비 메모리 사용량을 4.8~7.5배 줄이면서 토큰 생성 처리량은 1.6~2.1배 끌어올렸다고 보고한다. 최근 이 카테고리에서 다룬 '메모리 대역폭이 먼저 병목'이라는 LiteRT-LM 사례나 KV 캐시를 플래시로 옮기는 KVNAND와 같은 선상에서, 양자화만으로는 못 푸는 온디바이스 LLM 서빙의 메모리 문제를 다른 각도(디코딩 전략)에서 공략한 사례다."
    source_url: "https://arxiv.org/abs/2609.03079"
  - title: "완전 학습형 코덱은 모바일에서 크래시가 난다 — LEAN-3D가 얕은 층만 신경망에 맡기는 이유"
    type: "논문"
    summary: "라이다 포인트클라우드를 모바일/엣지에서 실시간 스트리밍하려면 압축이 필요한데, 완전 학습형(neural) 코덱은 정밀도는 좋지만 플랫폼마다 부동소수점 연산 결과가 달라져 디코딩이 크래시나는 문제가 있다. LEAN-3D는 이를 절충해, 구조적 불확실성이 큰 얕은 계층(상위 octree 레벨)에만 가벼운 학습형 점유 모델을 쓰고 나머지 깊은 계층은 결정론적 코더로 처리하는 하이브리드 구조를 제안한다. Jetson Orin Nano 엣지 보드에서 기존 실시간 학습형 라이다 코덱 RENO 대비 인코딩 3.2~4.3배, 디코딩 3.5~5.1배 빨라지고 에너지 소비는 최대 5.1배 줄었으며, 비트 정확한 엔트로피 코딩으로 플랫폼 간 디코딩 실패도 없앴다고 보고한다. 지난주 다룬 Point4Bit(라이다 포인트클라우드 4비트 양자화)가 '검출 모델의 정확도'를 지키는 양자화 문제였다면, LEAN-3D는 같은 비-이미지 도메인에서 '스트리밍 자체의 레이턴시·에너지·크로스플랫폼 안정성'이라는 다른 종류의 엣지 제약을 다룬다는 점에서 상호보완적이다."
    source_url: "https://arxiv.org/abs/2604.04737"
